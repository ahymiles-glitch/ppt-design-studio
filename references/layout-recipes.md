# mode1 版式配方 — 快速实施指南

根据内容关系选择版式，不要因为某一种版式容易复用，就把每一页都做成同样的样子。

## 内容关系与版式选择

| 内容关系 | 推荐构图 | 避免 |
|---|---|---|
| 主题 + 目录 | 左侧大标题，右侧编号目录 | 整页项目符号列表 |
| 多种选择 / 职业路径 | 3–4 张错落纸片卡片 | 四个完全相同的应用界面卡片 |
| 定义 / 原则 | 左侧大观点，右侧三个编号问题 | 大段解释文字 |
| 人群 / 情境对比 | 三条横向粉彩信息带 | 拥挤的八列表格 |
| 流程 / 工作流 | 有方向的编号步骤 | 到处都是没有说明的箭头 |
| 证据 / 指标 | 一个图表或证据对象 + 结论 | 没有来源的装饰性信息图 |
| 结尾 | 一句记忆点 + 一到两个行动 | 只有“谢谢”两个字 |

## 构图比例参考

- 页面外边距：页面宽度的 4%–6%；
- 顶部页眉色带：页面高度的 10%–16%；
- 主标题区域：内容宽度的 35%–55%；
- 辅助信息栏：内容宽度的 35%–50%；
- 主标题周围和页面边缘保留安静的留白区。

## 短篇演示文稿的常见叙事顺序

适用于 5–8 页左右的分享：
1. 封面：这是什么，为什么值得听；
2. 目录 / 路线：观众接下来如何理解内容；
3. 背景或个人起点；
4. 核心观点 / 框架 / 角色定义；
5. 证据、案例或对比；
6. 行动方案或差异化路径；
7. 结尾原则与下一步。

按原始资料调整顺序，不要为了凑到七页硬加页面。

## 文字结构化示例

**原始表述：**“产品经理负责需求分析、协调研发、推动项目上线，并根据用户反馈不断优化产品。”

**可以转化为：**
- 标题：“产品经理要把业务问题变成可落地的产品方案”
- 做什么：识别最值得解决的问题
- 怎么做：协调信息、资源与方案
- 如何推进：推动上线并根据反馈迭代

这是版式转化示例，不是适用于所有公司的岗位定义。实际内容必须以用户资料为准。

## 视觉实现提示

- 顶部色带、标签页、卡片、分隔线、星芒和回形针优先使用 PowerPoint 原生形状。
- 回形针使用细线圆角路径或克制 SVG，不要使用实心粗图标。
- 星芒使用少量可复用形状，不要随机撒满页面。
- 卡片可以少量错位，不要大角度旋转。
- 每页只设置一个主色块，其他颜色用于区分有意义的信息组。
- 图表沿用深可可棕和粉彩体系，但保留标准图表表达、来源和单位。
- 页眉、目录、栏目名、标签等界面文字默认使用自然简体中文。
